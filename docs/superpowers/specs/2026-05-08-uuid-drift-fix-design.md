# UUID Drift Reconciliation — Design Spec

**Date:** 2026-05-08
**Branch (proposed):** `fix/uuid-drift`
**Migration tag:** `0007_fix_user_id_uuid_drift`
**Neon project:** `cool-wind-76972110` (org `org-withered-dream-72376224`)

---

## 1. Background

PR #6 (`feat-parent-account`, merged as `2f6803e` on `main`) was just applied to Neon prod. During application, the migration file had to be deviated from to make it succeed:

- `neon_auth.user.id` is provisioned by Neon Auth as `uuid`, but `apps/web/src/db/schema.ts:21` declared `neonAuthUsers.id` as `text("id")`. This drift predates PR #6.
- Every column declared in schema.ts as `text` while `references(() => neonAuthUsers.id, ...)` could not attach an FK in Postgres (mismatched types fail silently from drizzle-kit's perspective).
- To make PR #6's migration apply: `orders.user_id` was ALTERed `text → uuid` (empty data), `parent_children.parent_id` was created as `uuid` instead of `text`. `order_refunds.operator_user_id` was left untouched — still `text`, still no FK.

After PR #6:

| Column | DB type | schema.ts | FK in DB |
|---|---|---|---|
| `neon_auth.user.id` | `uuid` | `text("id")` | n/a (PK) |
| `orders.user_id` | `uuid` | `text("user_id")` | yes, `ON DELETE SET NULL` |
| `parent_children.parent_id` | `uuid` | `text("parent_id")` | yes, `ON DELETE CASCADE` |
| `order_refunds.operator_user_id` | `text` | `text("operator_user_id")` | **no** (silently failed) |

`apps/web/drizzle/meta/0006_snapshot.json` mirrors schema.ts (text everywhere), so future `drizzle-kit generate` runs will not see drift — but the snapshot is not faithful to production.

## 2. Goal

Bring `apps/web/src/db/schema.ts` and the drizzle snapshot in line with Neon prod reality, and attach the missing `order_refunds.operator_user_id` FK.

## 3. Success criteria

- All 4 affected `user.id` reference columns declared as `uuid` in schema.ts.
- `order_refunds.operator_user_id` has a working FK to `neon_auth.user(id)` `ON DELETE SET NULL` in prod.
- `pnpm --filter web exec drizzle-kit generate` from a clean tree produces no spurious migration.
- The `drizzle.__drizzle_migrations` table in prod contains a row for `0007_fix_user_id_uuid_drift` whose hash equals the SHA-256 of the file shipped in the repo.
- `pnpm check-types:web` passes.

## 4. Out of scope

- **`tablesFilter` / `schemaFilter` cleanup.** Excluding `neon_auth.*` from drizzle-kit so it stops considering foreign-managed tables on every generate is a separate, exploratory PR. Tracked at `docs/remaining_work.md` §4.11. Worth doing carefully because the failure mode (drizzle-kit emitting `DROP TABLE neon_auth.user`) is catastrophic.
- Refactoring `neonAuthUsers` declaration to a separate file or `sql\`\`` literal FK references — also part of §4.11 if needed.
- Any changes to other columns or tables.

## 5. Architecture

Two coordinated changes, one PR:

### 5.1 Schema (`apps/web/src/db/schema.ts`)

Four single-token edits, `text` → `uuid`:

| Line | Before | After |
|---|---|---|
| 21 | `id: text("id").primaryKey(),` | `id: uuid("id").primaryKey(),` |
| 136 | `userId: text("user_id").references(() => neonAuthUsers.id, { onDelete: "set null" }),` | `userId: uuid("user_id").references(() => neonAuthUsers.id, { onDelete: "set null" }),` |
| 180 | `operatorUserId: text("operator_user_id").references(() => neonAuthUsers.id, { onDelete: "set null" }),` | `operatorUserId: uuid("operator_user_id").references(() => neonAuthUsers.id, { onDelete: "set null" }),` |
| 196 | `parentId: text("parent_id")` | `parentId: uuid("parent_id")` |

`uuid` is already imported at line 11. No import change.

### 5.2 Migration (`apps/web/drizzle/0007_fix_user_id_uuid_drift.sql`)

Generated by `pnpm --filter web exec drizzle-kit generate --name=fix_user_id_uuid_drift`. drizzle-kit diffs schema.ts against snapshot[0006] — **not against the live database.** Both already declare each FK as present, so the diff will emit column-type changes only. For each FK column, drizzle is also free to emit `DROP CONSTRAINT … / ALTER COLUMN … TYPE uuid / ADD CONSTRAINT …` triplets (Postgres often requires this dance to retype a column under an FK).

**Treat whatever drizzle-kit emits as authoritative**, modulo the §5.3 hand-edits. Do not substitute hand-written equivalents.

DB-vs-statement reality:

| Column | DB type today | FK in prod today | Statement effect | Action |
|---|---|---|---|---|
| `neon_auth.user.id` | `uuid` | n/a (PK) | no-op ALTER | **strip from migration before applying** (foreign-managed schema) |
| `orders.user_id` | `uuid` | yes | no-op ALTER (or DROP/ALTER/ADD triplet) | apply verbatim |
| `parent_children.parent_id` | `uuid` | yes | no-op ALTER (or DROP/ALTER/ADD triplet) | apply verbatim |
| `order_refunds.operator_user_id` | `text` | **no** | drizzle emits ALTER (and may emit DROP+ADD pretending the FK exists) | apply with `NULLIF` cast; **explicitly add the missing FK**; convert any `DROP CONSTRAINT order_refunds_operator_user_id_user_id_fk` to `DROP CONSTRAINT IF EXISTS` since the FK does not exist in prod |

### 5.3 Hand-edits to the generated SQL

Four adjustments after `drizzle-kit generate`:

1. **Strip the `neon_auth.user` ALTER** (if drizzle-kit emits one). We do not run DDL against the foreign-managed `neon_auth` schema. Its absence from the migration file is recorded; structural fix is §4.11.
   - **Snapshot/SQL asymmetry:** the stripped DDL leaves `0007_snapshot.json` correctly recording `neon_auth.user.id` as `uuid`, while `0007_*.sql` does not contain the corresponding ALTER. This asymmetry is intentional — prod already aligns with the snapshot for that column, and we never run DDL against `neon_auth`. A future reader who notices the asymmetry should land on §4.11.

2. **Force defensive `USING` for `order_refunds.operator_user_id` cast.** Replace whatever drizzle emits with `USING NULLIF("operator_user_id", '')::uuid`. Costs nothing on empty data; protects against any row arriving between verify-time and apply-time.

3. **Convert any `DROP CONSTRAINT order_refunds_operator_user_id_user_id_fk` to `DROP CONSTRAINT IF EXISTS`.** drizzle-kit may emit a plain DROP because snapshot[0006] declares the FK; that DROP would fail in prod since the FK never attached. `IF EXISTS` makes the statement a safe no-op there.

4. **Ensure exactly one post-ALTER `ADD CONSTRAINT` for the `order_refunds` FK is present in the file.** drizzle-kit's diff cannot see the prod gap (snapshot declares the FK as already present), so the file may or may not include the ADD depending on drizzle-kit version and whether it emits a DROP/ALTER/ADD triplet for the column.
   - **If drizzle emits the triplet** (DROP CONSTRAINT + ALTER COLUMN TYPE + ADD CONSTRAINT) for `order_refunds.operator_user_id`: keep its ADD verbatim. (Step 3 above still converts the DROP to `IF EXISTS`.) Do not hand-add another.
   - **If drizzle emits only the ALTER COLUMN TYPE** (no ADD CONSTRAINT): hand-append the statement below at the end of the `order_refunds` block, before the migrations-table INSERT:

     ```sql
     ALTER TABLE order_refunds
     ADD CONSTRAINT order_refunds_operator_user_id_user_id_fk
     FOREIGN KEY (operator_user_id)
     REFERENCES neon_auth."user"(id)
     ON DELETE SET NULL;
     ```

   Whichever path, the ADD must run **after** the column-type ALTER (Postgres requires both sides of an FK to share a type). Pre-flight guarded by §6 step 3.

### 5.4 drizzle.config.ts

**Unchanged.** The narrowest fix possible. Cleanup tracked at `docs/remaining_work.md` §4.11.

## 6. Apply procedure (Neon prod `cool-wind-76972110`)

0. **Generate the migration file and apply hand-edits.** From repo root:
   ```bash
   pnpm --filter web exec drizzle-kit generate --name=fix_user_id_uuid_drift
   ```
   This produces `apps/web/drizzle/0007_fix_user_id_uuid_drift.sql` plus updated `_journal.json` and `0007_snapshot.json`. Apply the four §5.3 hand-edits to the `.sql` file before continuing. Verify `0007_snapshot.json.prevId == 0006_snapshot.json.id`.

1. Compute file hash:
   ```bash
   shasum -a 256 apps/web/drizzle/0007_fix_user_id_uuid_drift.sql
   ```
2. Read `when` millis for the new entry in `apps/web/drizzle/meta/_journal.json`.
3. **Pre-flight gates** via `mcp__Neon__run_sql`:
   ```sql
   SELECT COUNT(*) FROM order_refunds;
   ```
   Expected: `0`. If non-zero, abort and re-evaluate the `NULLIF` cast.
   ```sql
   SELECT conname, pg_get_constraintdef(oid) AS def
   FROM pg_constraint
   WHERE conrelid = 'order_refunds'::regclass
     AND contype = 'f'
     AND conname = 'order_refunds_operator_user_id_user_id_fk';
   ```
   Decision tree:
   - **Zero rows** (expected — this is the gap we're closing) → proceed; the §5.3-step-4 ADD CONSTRAINT must end up applied.
   - **One row, `def` exactly matches** `FOREIGN KEY (operator_user_id) REFERENCES neon_auth."user"(id) ON DELETE SET NULL` → FK already attached correctly; **strip** any ADD CONSTRAINT for this FK from the apply transaction (drizzle's or hand-added) to avoid a duplicate-constraint error.
   - **One row, `def` differs** → abort. A wrong-shaped FK is in place; surface it for human review before continuing.

4. Atomic apply via `mcp__Neon__run_sql_transaction` (project `cool-wind-76972110`), statements split as separate array elements **in this order** (transcribe verbatim from the post-hand-edit `0007_*.sql`; the order below is what drizzle-kit's diff plus the §5.3 hand-edits should produce):

   1. `ALTER TABLE orders ALTER COLUMN user_id TYPE uuid USING "user_id"::uuid;` — no-op in prod, but present in the file (drizzle-kit diffs `text`→`uuid` against snapshot[0006]). Include any DROP/ADD triplet drizzle-kit emits around it.
   2. `ALTER TABLE parent_children ALTER COLUMN parent_id TYPE uuid USING "parent_id"::uuid;` — same: no-op in prod, present in file. Include any DROP/ADD triplet.
   3. `ALTER TABLE order_refunds ALTER COLUMN operator_user_id TYPE uuid USING NULLIF("operator_user_id", '')::uuid;` — **must run before** the ADD CONSTRAINT below.
   4. `ALTER TABLE order_refunds ADD CONSTRAINT order_refunds_operator_user_id_user_id_fk FOREIGN KEY (operator_user_id) REFERENCES neon_auth."user"(id) ON DELETE SET NULL;`
   5. `INSERT INTO drizzle.__drizzle_migrations (hash, created_at) VALUES ('<sha256>', <when-millis>);`

   The `0007_*.sql` file (after hand-edits) is authoritative. The list above describes the expected shape; transcribe what's actually in the file.

## 7. Verification

After apply:

- **Type-check:**
  ```bash
  pnpm check-types:web
  ```
  Must pass. Drizzle's `uuid` column type maps to TS `string`, identical to `text`, so no downstream call-site changes are required.

- **Column types** via `mcp__Neon__run_sql`:
  ```sql
  SELECT table_schema, table_name, column_name, data_type
  FROM information_schema.columns
  WHERE (table_name = 'order_refunds'   AND column_name = 'operator_user_id')
     OR (table_name = 'orders'          AND column_name = 'user_id')
     OR (table_name = 'parent_children' AND column_name = 'parent_id')
     OR (table_schema = 'neon_auth' AND table_name = 'user' AND column_name = 'id');
  ```
  All 4 rows must report `data_type = 'uuid'`.

- **Foreign key on `order_refunds`:**
  ```sql
  SELECT conname, pg_get_constraintdef(oid)
  FROM pg_constraint
  WHERE conrelid = 'order_refunds'::regclass AND contype = 'f';
  ```
  Must include `order_refunds_operator_user_id_user_id_fk` referencing `neon_auth.user(id) ON DELETE SET NULL`.

- **Migration recorded:**
  ```sql
  SELECT hash, created_at
  FROM drizzle.__drizzle_migrations
  ORDER BY created_at DESC
  LIMIT 3;
  ```
  Top row's hash must equal the computed SHA-256 of `apps/web/drizzle/0007_fix_user_id_uuid_drift.sql`.

- **Snapshot chain:** open `apps/web/drizzle/meta/0007_snapshot.json` and verify `prevId` equals the `id` field of `apps/web/drizzle/meta/0006_snapshot.json`.

- **Clean-tree generate:** with `0007` applied locally, `pnpm --filter web exec drizzle-kit generate` from a clean working tree must produce no new migration. (Acceptance gate for "schema and snapshot now agree.")

## 9. Risks & mitigations

| Risk | Mitigation |
|---|---|
| **drizzle-kit will not emit `ADD CONSTRAINT` for the missing prod FK on `order_refunds.operator_user_id`** because `0006_snapshot.json` already records it as present (snapshot vs. reality mismatch). Without action the §3 success criterion silently fails. | Hand-add the `ADD CONSTRAINT` statement (§5.3 step 4); pre-flight verifies it does not already exist (§6 step 3). |
| drizzle-kit may emit `DROP CONSTRAINT order_refunds_operator_user_id_user_id_fk` (DROP/ALTER/ADD triplet) — would fail in prod since the FK is absent. | §5.3 step 3: convert to `DROP CONSTRAINT IF EXISTS`. |
| `order_refunds` gains a row between verify-time and apply-time | Pre-flight `COUNT(*)` gate (§6 step 3); `NULLIF("operator_user_id", '')::uuid` makes any empty-string row castable to `NULL`. |
| Drizzle-kit emits ALTER for `neon_auth.user.id` | Hand-strip from `0007_*.sql` before applying (§5.3 step 1); snapshot/SQL asymmetry is intentional and documented; structural follow-up at §4.11. |
| 0007 snapshot chain breaks | Verify `0007_snapshot.json.prevId == 0006_snapshot.json.id` immediately after generate (§6 step 0, §7). |
| Type-check regression downstream | None expected — drizzle's `uuid` and `text` both map to TS `string`. Verified via `pnpm check-types:web` as the acceptance gate. |
| Migration recorded but file lost (sha mismatch later) | The `_journal.json` and `0007_*.sql` are committed in the same atomic PR as the schema change; the SHA-256 is computed from the committed file. |
