## Allow 127.0.0.1 as a Next.js allowedDevOrigin so Playwright hydrates
- **ID:** a8708d49-29af-4e12-bcb3-03b919120d0b
- **Date:** 2026-09-07T12:17:36Z
- **Stage:** build:M05
- **Decision:** Set allowedDevOrigins to 127.0.0.1, localhost, and the LAN IP in next.config.ts. Also skip security headers on /_next/* so the HMR websocket upgrade is not rewritten.
- **Why:** Next 16 treats 127.0.0.1 as a different origin from localhost and rejects the Turbopack HMR handshake (HTTP/0.9 / ERR_INVALID_HTTP_RESPONSE). Client islands then never hydrate: Browse Catalogue, qty stepper, Add to cart. localhost:3000 already worked; Playwright defaults to 127.0.0.1:3000.
- **Alternatives:** Force all tools to localhost only; disable nonce CSP in dev; switch off Turbopack.
- **Pros:** Playwright, playwright-cli, and agents using 127.0.0.1 hydrate. Production headers unchanged.
- **Cons:** Widens allowed HMR origins in development.
- **Risks / known issues:** LAN IP 192.168.50.45 is machine-local; other machines should add their own if needed.
- **Links:** apps/web/next.config.ts; specs/milestones/M05-parent-preloved-shop.md
