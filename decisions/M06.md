## Paid decrement is one neon-http SQL CAS keyed by payment_intent_id, not db.batch
- **ID:** 8839cfda-0505-4300-b92c-67f73fdbbb27
- **Date:** 2026-09-07T14:00:21Z
- **Stage:** build:M06
- **Decision:** Add preloved_paid_decrements (payment_intent_id PK) and decrementPrelovedForPaymentIntent in preloved-queries.ts. One statement: pg_advisory_xact_lock, FOR UPDATE SKUs, qty-gated UPDATE, then INSERT the claim from UPDATE RETURNING. Call from POST /api/orders before insert and from payment_intent.succeeded. No sold intake action. No qty on catalog_variants.
- **Why:** Brief said db.batch; neon-http has no interactive transactions and db.batch of UPDATE+INSERT can partial-commit (M03). First impl claimed then unclaimed in one WITH; Postgres sibling CTEs cannot see the INSERT except via RETURNING, so unclaim matched nothing and a 409 retry looked already-applied. Implemented shape is claim-after-UPDATE (fix:1:2). Drift from brief db.batch is intentional.
- **Alternatives:** db.batch of per-SKU updates; reserve at PaymentIntent create; intake_events action=sold; claim-first then DELETE unclaim; plpgsql function
- **Pros:** Atomic on neon-http. Same-PI retries serialize. Failed CAS leaves no claim. Dual callers share one helper. GST/reports stay in queries.ts.
- **Cons:** Raw SQL beside Drizzle. Advisory lock extra-serializes hash collisions. Unique-conflict catch assumes pkey name.
- **Risks / known issues:** Journal idx 21 must be applied or runtime fails. Two last-unit PIs can both pass M05's non-locking read; CAS is the hard backstop. FOR UPDATE CTE must stay referenced by the final SELECT.
- **Links:** specs/milestones/M06-preloved-fulfilment.md; apps/web/src/db/preloved-queries.ts; apps/web/drizzle/0021_preloved_paid_decrements.sql; decisions/M03.md bbe4b22a

- **Why:** Spec allows fail PI or order create. Auto-refund with reverse_transfer on destination charges is a money-moving path out of this brief. Stripe retries forever if the webhook throws a terminal CAS fail.

## Webhook decrements snapshot-first; order_lines fallback; skip if both missing

- **Stage:** build:M06
- **Decision:** decrementPrelovedOnPaid reads pending_order_snapshots by PI id; else order_lines of the resolved order. Missing both skips. Same helper as POST /api/orders.
