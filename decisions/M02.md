## Sale-time gstFree is live donatedGstFree AND a valid donated preloved SKU; never the client flag
- **ID:** 0a07f8ba-cbc0-4bf6-96f5-eecc0fad70f9
- **Date:** 2026-09-06T15:43:58Z
- **Stage:** build:M02
- **Decision:** At PaymentIntent creation, a line is GST-free only when prelovedSkuId resolves to an active tenant SKU and donatedGstFree is true. Client gstFree is ignored. New catalogue lines stay taxable. SKU.gstFree listing-time copy is not the charge-time source.
- **Why:** Plan §8.2 / §12.6: GST-free is tenant-declared, default off, donated stock only. Listing-time sku.gstFree can be stale if the operator later ticks or unticks the setting.
- **Alternatives:** Trust client gstFree; freeze sku.gstFree at intake; AND sku.gstFree with the live flag.
- **Pros:** Matches the accountant checkbox; cannot launder new stock as GST-free; enabling the flag GST-frees current donated SKUs without a re-list.
- **Cons:** PI must read preloved settings + SKUs, not only the new-catalogue price map.
- **Risks / known issues:** M05 must send prelovedSkuId or preloved lines are priced as new.
- **Links:** specs/milestones/M02-mixed-cart-gst.md

## Fail-closed PaymentIntent creation if the pending snapshot insert fails; plain insert, no onConflict
- **ID:** 23ee3c5b-f6e3-46e4-bb9e-d3869ac3c934
- **Date:** 2026-09-06T15:43:59Z
- **Stage:** build:M02
- **Decision:** If pending_order_snapshots insert throws, cancel the PI (abandoned) and return 500 without clientSecret. Newly minted Stripe PI ids are unique, so skip onConflictDoNothing+SELECT.
- **Why:** Swallowing insert failure left a payable PI whose order POST forced gstFree:false and GST=total/11. onConflict+returning is empty on skip and was dead weight.
- **Alternatives:** Stamp gstFree onto Stripe metadata; keep onConflict+SELECT; return clientSecret anyway.
- **Pros:** DB snapshot is the single tax-flag carrier; Stripe metadata 500-char cap is not used.
- **Cons:** A leftover-row 500 is possible if cancel also fails.
- **Risks / known issues:** Low: PI ids do not reuse.
